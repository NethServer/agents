# ns8-nethvoice and ns8-nethvoice-proxy

Both modules follow the same flow. The examples use `nethesis/ns8-nethvoice` and version
`1.8.0`; for the proxy, change the repository.

## Testing releases

Every PR merged into `main` runs `create-testing-release.yml`, which creates the next
testing release. The name derives from the most recently **created** release:

- latest is stable `X.Y.Z` → `X.Y.(Z+1)-testing.1`
- latest is `X.Y.Z-testing.N` → `X.Y.Z-testing.(N+1)`

Consequences:

- A direct push to `main`, or a PR that changes only ignored paths (`.github/**`,
  `tests/**`, `README.md`, ...), creates no testing release. Its commit can still be the
  one to release: check its image build instead.
- The workflow never bumps the minor version. To start a new minor, create the first
  testing release by hand before the first merge of the cycle:
  `gh ns8 module-release create --repo nethesis/ns8-nethvoice --testing --release-name 1.9.0-testing.0`
- After a stable `1.8.0`, the next merge produces `1.8.1-testing.1` by itself.

## Version alignment

The proxy follows the NethVoice minor version: release proxy `1.8.0` with NethVoice
`1.8.0`, even if the proxy changes alone would be a patch. Patch versions are independent
afterwards (NethVoice `1.8.3` can run with proxy `1.8.1`).

## Before the stable release

1. Pick the commit to release, usually the `HEAD` of `main` after the last merge:
   ```bash
   gh api repos/nethesis/ns8-nethvoice/commits/main -q .sha
   ```
2. Check that the "Publish images" run of that commit succeeded:
   ```bash
   gh run list -R nethesis/ns8-nethvoice --commit <sha> --workflow publish-images.yml \
     --json event,status,conclusion
   ```
   The module image can exist while a sub-image group failed. To be sure, read the
   `org.nethserver.images` label of `ghcr.io/nethesis/nethvoice:<testing tag>` and check
   that every listed image exists. Rerun a failed group with `gh run rerun <run> --failed`.
3. Run `gh ns8 module-release check` and show the release blockers to the user.
4. Check that the documentation PRs of the milestone are merged or ready.

## Create the stable release

```bash
gh extension install NethServer/gh-ns8     # once
gh ns8 module-release create --repo nethesis/ns8-nethvoice \
  --release-name 1.8.0 --release-refs <sha> --with-linked-issues --draft
```

If the extension fails, create the same draft with plain `gh`:

```bash
gh release create 1.8.0 -R nethesis/ns8-nethvoice --draft --target <sha> --title 1.8.0 \
  --generate-notes --notes-start-tag 1.7.14
```

`--notes-start-tag` must be the previous **stable** release. Without it, GitHub can diff
against the latest testing release and the notes come out almost empty.

### Release notes

The notes contain, in this order:

1. `## Linked Issues`, one line per issue:
   `- [NethServer/dev#8190](https://github.com/NethServer/dev/issues/8190): <title>`.
   `--with-linked-issues` lists only the issues referenced in the PR bodies. Add the
   `verified` issues of the milestone that this component fixes, and remove the ones fixed
   only in another component (for example a NethLink-only issue).
2. `## What's Changed` and `**Full Changelog**`, generated by GitHub.
3. ns8-nethvoice only: the external components section. Take the commit from
   `nethcti-server/Containerfile` at the released commit, which is the one built into
   the image:
   ```bash
   git show <sha>:nethcti-server/Containerfile | grep NETHCTI_SERVER_COMMIT=
   ```
   ```markdown
   ### External components `HEAD`
   * https://github.com/nethesis/nethcti-server/commit/<commit>
   ```

Edit the draft with `gh release edit 1.8.0 -R <repo> --notes-file notes.md`, show it to
the user, and publish only after approval:

```bash
gh release edit 1.8.0 -R nethesis/ns8-nethvoice --draft=false --latest
```

Publishing creates the tag and starts "Publish images" for `1.8.0`. Check that it succeeds.

## Clean up the testing releases

After the stable release is published, delete the testing releases created since the
previous stable one:

```bash
gh ns8 module-release clean --repo nethesis/ns8-nethvoice --release-name 1.8.0
```

`clean` runs `gh release delete` without `--cleanup-tag`, so the tags and their images
stay. Neither repository cleans up automatically. When cleaning by hand, never pass
`--cleanup-tag`. Also look for testing releases left over by older cycles, for example
`1.7.9-testing.*` after `1.7.9` was released, and ask before deleting them too:

```bash
gh release list -R nethesis/ns8-nethvoice -L 500 --json tagName,isPrerelease \
  -q '[.[] | select(.isPrerelease) | .tagName | sub("-testing\\.[0-9]+$"; "-testing.*")]
      | group_by(.) | map("\(.[0]) x\(length)") | .[]'
```
